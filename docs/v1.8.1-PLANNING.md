# v1.8.1 Planning: Spread Import/Export

**Status:** Planning  
**Branch:** `feature/spread-import-export` (to be created)  
**Target Release:** TBD

## Overview

Add import/export functionality for custom spreads, mirroring the deck system from v1.8.0. Enable community sharing of spread definitions with optional template files.

## Goals

- **User Experience:** Easy spread sharing via JSON or ZIP files
- **Community Building:** Enable spread marketplace/repository
- **Template Bundling:** Include custom templates with spread exports
- **Backward Compatibility:** Existing spreads in settings continue to work
- **Familiar UX:** Mirror deck management interface

## User Workflows

### Export Workflow
```
1. Settings → Tarot Practice → Spread Management
2. Click on custom spread in list
3. Click "Export" button
4. Choose format: JSON only or ZIP with template
5. File downloads to computer
6. User can share on GitHub, Discord, forums, etc.
```

### Import Workflow
```
1. User downloads spread file from community
2. Settings → Tarot Practice → Spread Management
3. Click "Import spread" button
4. Select JSON or ZIP file
5. Spread validates and installs
6. Immediately available in spread selector
```

## Technical Approach

### File Structure

**Spread storage location:**
```
.obsidian/plugins/tarot-practice/
├── decks/              # Existing deck storage
│   └── {deck-id}/
│       └── deck.json
└── spreads/            # New spread storage
    └── {spread-id}/
        └── spread.json
```

**ZIP structure for sharing:**
```
celtic-cross.zip
├── spread.json         # Required: Spread definition
└── template.md         # Optional: Custom template for this spread
```

**Note on templates in vault:**
If spread.json references a templatePath, that's a vault path. The bundled template.md in the ZIP is imported to the vault at: `{templateBaseFolder}/Spreads/{spread-id}/template.md`

### Spread JSON Structure

```json
{
  "id": "custom-relationship",
  "name": "Relationship Spread",
  "description": "Explores dynamics between two people",
  "positions": [
    {
      "label": "You",
      "description": "How you show up in this relationship"
    },
    {
      "label": "Them", 
      "description": "How they show up in this relationship"
    },
    {
      "label": "Connection",
      "description": "The energy between you"
    }
  ],
  "shuffleCount": 3,
  "cutDeck": true,
  "templatePath": "Templates/Tarot/Spreads/relationship/template.md",
  "isBuiltIn": false,
  "metadata": {
    "author": "Jane Doe",
    "year": 2025,
    "tradition": "modern",
    "source": "Original creation"
  }
}
```

### Storage Strategy

**Hybrid approach (like decks):**
- Spread definition in `.obsidian/plugins/tarot-practice/spreads/{spread-id}/spread.json`
- Optional template in vault at `{templateBaseFolder}/Spreads/{spread-id}/template.md`

**Benefits:**
- Spread configs separate from vault (plugin-managed)
- Templates in vault (user can edit, sync, use wikilinks)
- Clean uninstall removes both config and template
- Template base folder respects user settings

### Validation Rules

**Required fields:**
- `id` - lowercase, hyphens only, unique
- `name` - display name
- `positions` - array with at least 1 position
- `positions[].label` - required for each position

**Optional but recommended:**
- `description` - what the spread is for
- `positions[].description` - meaning of each position
- `metadata.author` - who created it
- `metadata.tradition` - tarot, oracle, etc.

**Position validation:**
- At least 1 position required
- Maximum 78 positions (full deck)
- Each position must have a label
- Position order matters (index 0, 1, 2...)

### Edge Cases

- [ ] Spread ID collision → Prompt to overwrite or rename
- [ ] ZIP without spread.json → Error with clear message
- [ ] ZIP with invalid spread.json → Validation errors shown
- [ ] Template path in spread.json doesn't exist → Use built-in
- [ ] Corrupted ZIP → Catch errors, show notice
- [ ] Large ZIP files → Handle async, show progress
- [ ] Export spread without template → JSON export only
- [ ] Import spread with duplicate position labels → Warning (allowed)
