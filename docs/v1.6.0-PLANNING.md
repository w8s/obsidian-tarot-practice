# v1.6.0 Planning: Card Metadata & Querent Tracking

**Goals:** 
1. Enhance card data structure with metadata (category, suit, rank, value) to enable richer templating and future analytics
2. Add optional querent tracking for readings done for others

---

## Overview

### Card Metadata Enhancement

Currently, cards are just strings in an array. This limits templating capabilities and makes it impossible to filter or analyze by suit, rank, or other attributes.

**Current state:**
```typescript
RWS_CARDS[22] = "Ace of Wands"  // Just a string
```

**Target state:**
```typescript
{
  index: 22,
  name: "Ace of Wands",
  category: "Minor",
  suit: "Wands",
  rank: "Ace",
  value: 1
}
```

### Querent Tracking

Add optional querent field to readings for tracking who the reading is for. Useful for professional readers or personal practice tracking readings for friends/family.

**Current state:**
No way to track who a reading is for

**Target state:**
```typescript
{
  querent?: {
    name: string;      // "Sarah Chen"
    notePath?: string; // "People/Sarah Chen"
  }
}
```

## Data Structure

### CardDefinition Interface

```typescript
interface CardDefinition {
  /** Zero-based index in the deck (0-77 for RWS tarot) */
  index: number;
  
  /** Full card name (e.g., "Ace of Wands", "The Fool") */
  name: string;
  
  /** 
   * Deck-specific grouping/category
   * - Tarot: "Major" or "Minor"
   * - Runes: "Freyr's Aett", "Heimdall's Aett", "Tyr's Aett"
   * - Oracle: null or theme name ("Heart Chakra", "Abundance")
   * - Playing Cards: null
   */
  category?: string | null;
  
  /**
   * Suit name for applicable cards
   * - Tarot Minor Arcana: "Wands", "Cups", "Swords", "Pentacles"
   * - Playing Cards: "Hearts", "Diamonds", "Clubs", "Spades"
   * - Tarot Major Arcana: null
   * - Oracle: null
   */
  suit?: string | null;
  
  /**
   * Rank name for numbered/court cards
   * - Values: "Ace", "Two", "Three", ..., "Ten", "Page", "Knight", "Queen", "King"
   * - Major Arcana: null
   * - Oracle: null
   */
  rank?: string | null;
  
  /**
   * Numeric value for comparisons and sorting
   * - Minor Arcana: 1-14 (Ace=1, Two=2, ..., Page=11, Knight=12, Queen=13, King=14)
   * - Major Arcana: 0-21 (matches index) OR null (TBD)
   * - Oracle: null
   */
  value?: number | null;
}
```

## RWS Tarot Card Metadata

### Major Arcana (0-21)

```typescript
{
  index: 0,
  name: "The Fool",
  category: "Major",
  suit: null,
  rank: null,
  value: 0  // or null? TBD
}
```

**Decision needed:** Should Major Arcana have:
- **Option A:** `value: 0-21` (same as index) - enables numeric comparisons
- **Option B:** `value: null` - emphasizes they're not numerically comparable like Minor Arcana

**Recommendation:** Option A (value = index) because:
- Some readers do use Major Arcana numbers (numerology)
- Enables "show me high-numbered Majors" type queries
- Doesn't prevent treating them differently if needed

## Querent Feature

### Data Structure

Add querent information to DrawResult interface:

```typescript
interface DrawResult {
  // ... existing fields ...
  querent?: {
    name: string;      // Required: "Sarah Chen"
    notePath?: string; // Optional: "People/Sarah Chen"
  };
}
```

### UI Flow

**In spread draw modal (before intention prompt):**

1. Show checkbox: "Reading for someone else?"
2. If unchecked (default): Skip querent, proceed to intention
3. If checked: Show querent fields:
   - Name (text input, required)
   - Note path (text input, optional, placeholder: "People/Name")
   - Helper text: "Optional: Link to a note about this person"

**Implementation notes:**
- Add to IntentionModal or create separate QuerentModal
- Pass querent data through to DrawResult
- Include in template context

### Template Variables

Add to template context in SpreadFormatter:

```typescript
const templateData = {
  // ... existing fields ...
  querent: result.querent
    ? {
        name: result.querent.name,
        notePath: result.querent.notePath ?? '',
        hasPath: !!result.querent.notePath
      }
    : null
};
```

**Template usage examples:**

```handlebars
{{#if querent}}
**Querent:** {{#if querent.hasPath}}[[{{querent.notePath}}|{{querent.name}}]]{{else}}{{querent.name}}{{/if}}
{{/if}}
```

Or simplified:
```handlebars
{{#if querent}}
**Reading for:** {{querent.name}}
{{/if}}
```

### Benefits

- **Backlink tracking:** Links to People/ notes create automatic reading history
- **Professional workflow:** Track client readings
- **Personal use:** Track readings for friends/family
- **Optional:** Doesn't clutter interface when not needed
- **Flexible:** Works with or without vault organization

## Open Questions

### 1. Major Arcana Values
**Question:** Should Major Arcana have numeric values?
- **Option A:** `value: 0-21` (matches index)
- **Option B:** `value: null`

**Recommendation:** Option A for numerology support

### 2. Suit Capitalization
**Question:** "Wands" or "wands"? "WANDS"?

**Recommendation:** Title case ("Wands") - matches card name conventions

### 3. Category Naming
**Question:** For tarot, use:
- "Major" / "Minor"
- "Major Arcana" / "Minor Arcana"  
- "major" / "minor"

**Recommendation:** "Major" / "Minor" - shorter, cleaner in templates

### 4. Null vs Empty String
**Question:** For missing metadata, use `null` or `""`?

**Recommendation:** 
- Use `null` in TypeScript/data
- Coerce to `""` in templates for easier Handlebars conditionals
