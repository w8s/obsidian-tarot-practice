# v1.7.0 Planning: Multi-Deck Support

**Status:** Planning
**Goal:** Enable users to load and use custom decks (Oracle, Lenormand, custom tarot, etc.) from JSON files

---

## Overview

v1.6.1 gave us the `DeckDefinition` infrastructure. Now we make it user-facing: allow users to add custom decks via JSON files in their vault and choose which deck to use.

**Key principle:** Start simple. Support loading decks from JSON, basic deck selection UI, and per-spread deck choice.

---

## Goals

1. **Deck Loading** - Read DeckDefinition JSON files from vault
2. **Deck Registry** - Manage multiple decks (built-in + custom)
3. **Deck Selector UI** - Settings interface to view and manage decks
4. **Per-Spread Deck Selection** - Choose deck when drawing spreads
5. **Validation** - Ensure loaded decks are valid and complete

---

## User Stories

### As a tarot practitioner, I want to...
- Use my favorite Oracle deck (Sacred Rebels, Wild Unknown, etc.)

- Load custom decks without writing code

## Deck File Format

### Location
Custom decks stored in plugin directory:
- **Path:** `.obsidian/plugins/tarot-practice/decks/`
- **Not user-configurable** - managed by plugin
- **Installation:** Users add decks via "Add Deck" button in settings (file picker)

### Installation Workflow
1. User creates deck JSON file (anywhere on their system)
2. Settings → Deck Management → "Add Deck" button
3. File picker opens to select JSON file
4. Plugin validates the deck
5. If valid: Plugin copies file to `decks/` folder and loads it
6. If invalid: Show error message, don't copy file

### File Format
JSON files matching the `DeckDefinition` interface:

```json
{
  "id": "sacred-rebels-oracle",
  "name": "Sacred Rebels Oracle",
  "description": "Oracle deck by Alana Fairchild for spiritual rebels and change makers",
  "cards": [
    {
      "index": 0,
      "name": "The Great Stupa",
      "category": "Oracle",
      "suit": null,
      "rank": null,
      "value": null
    },
    {
      "index": 1,
      "name": "Soul Truth",
      "category": "Oracle",
      "suit": null,
      "rank": null,
      "value": null
    }
    // ... more cards
  ],
  "cardCount": 44,
  "supportsReversals": false,
  "isBuiltIn": false,
  "metadata": {
    "author": "Alana Fairchild",

```

## Data Structure

### DeckRegistry

```typescript
class DeckRegistry {
  private decks: Map<string, DeckDefinition>;
  
  // Initialize with built-in RWS deck
  constructor() {
    this.decks = new Map();
    this.registerDeck(RWS_DECK);
  }
  
  // Register a deck (built-in or custom)
  registerDeck(deck: DeckDefinition): void;
  
  // Get deck by ID
  getDeck(id: string): DeckDefinition | undefined;
  
  // Get all decks
  getAllDecks(): DeckDefinition[];
  
  // Get built-in decks only
  getBuiltInDecks(): DeckDefinition[];
  
  // Get custom (user-added) decks only
  getCustomDecks(): DeckDefinition[];
  
  // Remove a custom deck
  removeDeck(id: string): boolean;
  
  // Reload all custom decks from vault
  async loadCustomDecks(deckFolder: string): Promise<void>;
}
```

### Settings Extension

```typescript
interface TarotPracticeSettings {
  // ... existing settings ...
  
  // NEW: Deck management
  // Note: deckFolder is NOT configurable - always plugin directory
  defaultDeckId: string;           // Default: "rider-waite-smith"
  rememberDeckPerSpread: boolean;  // Default: true
  perSpreadDeckIds: {              // Deck override per spread (if rememberDeckPerSpread=true)
    [spreadId: string]: string;    // spreadId -> deckId
  };
  ignoredDeckWarnings: string[];   // Deck IDs to ignore duplicate name warnings for
}
```

## Implementation Plan

### Phase 1: Deck Registry & Loading

**Files to create:**
1. `src/core/DeckRegistry.ts` - Deck management class
2. `src/core/DeckLoader.ts` - JSON file loading and validation
3. `src/core/DeckValidator.ts` - Validate deck definitions

**DeckLoader responsibilities:**
- Read JSON files from plugin's `decks/` directory
- Parse and validate against DeckDefinition schema
- Return validated decks or error messages
- Handle malformed JSON gracefully
- Copy user-selected JSON files into `decks/` directory (installation)
- Provide file picker for deck installation

**DeckValidator checks:**
- Required fields present (id, name, cards, cardCount)
- cardCount matches cards.length
- All cards have required fields (index, name)
- Card indices are sequential (0 to cardCount-1)
- No duplicate card indices
- No duplicate card names (warning only)

## User Workflow

### Loading a Custom Deck

1. Create or download deck JSON file (anywhere on system)
2. Settings → Tarot Practice → Deck Management
3. Click "Add Deck" button
4. File picker opens - select your JSON file
5. Plugin validates the deck:
   - ✅ Valid: Deck copied to plugin directory and loaded
   - ❌ Invalid: Error message shown, file not copied
6. Deck appears in "Available Decks" list

### Using a Custom Deck

**Option A - Set as default:**
1. Settings → Deck Management → Default Deck dropdown
2. Select custom deck
3. All future draws use this deck (unless overridden)

**Option B - Per-spread selection:**
1. Run "Draw tarot spread"
2. Select deck from dropdown
3. Select spread
4. Enter intention

### Creating a Custom Deck

1. Settings → Deck Management → "Export Example Deck"
2. Choose template (Oracle, Lenormand, Playing Cards)
3. Choose where to save the file (file picker)
4. Edit the JSON file to add your cards
5. Use "Add Deck" to install it

## Validation & Error Handling

### Validation Errors

**Critical errors (deck not loaded):**
- Missing required fields (id, name, cards, cardCount)
- Invalid JSON syntax
- cardCount doesn't match cards.length
- Duplicate card indices
- Card indices not sequential

**Warnings (deck loaded but flagged):**
- Duplicate card names
- Missing optional metadata
- Unusual card count (< 10 or > 100)

### User Feedback

**Success:**
```
✓ Loaded 2 custom decks
- Sacred Rebels Oracle (44 cards)
- Lenormand (36 cards)
```

**Errors:**
```
✗ Failed to load 'my-deck.json'
  Error: cardCount (50) doesn't match cards.length (49)
  
✗ Failed to load 'broken.json'
  Error: Invalid JSON syntax at line 23
```

## Open Questions

### 1. Deck Installation Location
**Question:** Where should custom decks be stored?
- **Option A:** Plugin directory (`.obsidian/plugins/tarot-practice/decks/`)
- **Option B:** Vault visible (`Decks/` folder)
- **Option C:** `.obsidian/decks/` (root level)

**Decision:** ✅ Option A - Plugin directory with "Add Deck" installation workflow
- Clean separation of plugin data
- No vault clutter
- Clear installation process via file picker

### 2. Deck File Validation Strictness
**Question:** How strict should validation be?
- **Option A:** Strict - reject any deck with warnings
- **Option B:** Permissive - load deck with warnings, show notice
- **Option C:** Configurable - setting for validation level

**Decision:** ✅ Option B - Load with warnings, but inform user
- More forgiving for edge cases
- Users can still use decks with minor issues
- Clear feedback about potential problems

### 3. Deck Selection Persistence
**Question:** Should last-used deck be remembered per spread?
- **Option A:** Yes - remember per spread
- **Option B:** No - always use default
- **Option C:** Configurable setting

**Decision:** ✅ Option C - Configurable setting
- Setting: "Remember last deck per spread" (toggle, default: ON)
- Flexible - users can choose their preferred behavior
- Power users get convenience, minimalists get predictability

### 4. Duplicate Card Names
**Question:** Should duplicate card names be allowed?
- **Option A:** Block - reject deck with duplicates
- **Option B:** Warn - allow but show warning
- **Option C:** Silent - allow without warning

**Decision:** ✅ Option B - Warn but allow (with ignore option)
- Show warning notice when loading deck with duplicates
- Include "Don't show this again" checkbox in warning
- Store ignored deck IDs in settings to avoid nagging
- Some decks intentionally have duplicate names
- Example warning: "Sacred Rebels Oracle has 2 cards named 'Transformation' ☐ Don't show for this deck"
